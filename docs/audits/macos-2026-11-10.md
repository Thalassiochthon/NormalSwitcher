# macOS release audit — 10 November 2026

Scope covers the task MVP in PR #1, clipboard history, settings/navigation,
keyboard conversion paths, dictionaries, update checks, and release tooling.
Baseline was commit f655a5d on macos/clipboard-tasks-mvp, based on personal df3dd73.
This audit includes source review, a local build, and isolated regression tests.
The feature is available as opt-in beta 1.2.0a; stable promotion still awaits
interaction and upgrade verification.

## Product assessment

Capturing a copied thought is a coherent extension of clipboard history. The
existing task model supports an intentionally small workflow with active and
completed items. Projects, accounts, sync, attachments, and reminders can wait.

The capture/retrieval loop now has a compact clipboard window, eight recent
entries by default, search across the full history, and a direct Add to Tasks
button. Task settings have a named group and Open Tasks action; both shortcuts
can be changed or disabled. Opening a task works through its title or Return on
a selected row. The empty state explains capture, and previews omit an identical
first-line title. Projects, sync, source metadata, and reminders remain out of
scope for this MVP.

The task window has a fixed 480 × 360 content area, internal scrolling, and bounded
row previews. Isolated offscreen renders of the task/history/settings views were
exercised in light/dark appearances with synthetic text. Native-control capture was incomplete, so those images do
not establish production visual quality or keyboard accessibility. Live review
is still required.

## Corrected in this audit

| Finding | Trigger and consequence | Change |
|---|---|---|
| Deleted tasks could reappear | Open a task, delete it through capture Undo, then save the older editor. The upsert recreated it. | Separate creation and editing. An edit to a missing ID fails and retains the draft. |
| Editor could restore an older completion state | Edit a draft captured before a task state change. | Edit only title/body. Completion changes use a separate operation. |
| Another running copy could lose newer tasks | Two copies load the same file, then each saves its own list. | Compare the last successfully read file under an nonblocking exclusive advisory lock before writing. Conflicts require reload. |
| Key loss could silently rotate encryption | Load tasks, lose the Keychain item, then save. The old code allowed key creation on every save. | Existing files require the existing key. Failure preserves both disk and in-memory data. |
| Read/write errors had no clear recovery | Generic error followed by an apparently empty list or failed edits. | Retry/reload actions and explicit conflict/missing-task messages. Empty-state text is suppressed while an error is shown. |
| Editor Cancel discarded changes immediately | Change text and press Cancel/Escape. | Ask before discarding a dirty draft and disable interactive sheet dismissal while dirty. |
| Task file permissions were implicit | A new encrypted file inherited default permissions. | Write a private temporary file, then rename it under the lock. No fallible work follows the committed rename. |
| Mutable values captured by the text injection queue | Swift emitted concurrency diagnostics for two closures. | Capture immutable deletion count and replacement text. This removes the warnings without claiming a reproduced runtime race. |
| Stale upstream beta feed | With beta enabled, inherited version 3.5.0g wins over independent stable 1.1.6. | Remove the stale beta manifest in the draft branch. The updater already falls back to stable when this optional file is absent. The published personal feed still needs this cleanup merged. |
| macOS still used the old GitHub account URLs | Feed, dictionaries, and release links depended on redirects. | Use Thalassiochthon URLs while preserving application ID, preference keys, and signing team. |
| Inherited release commands pointed upstream | create_dmg.sh expected RuSwitcher.app; publish_release.sh targeted rashn/RuSwitcher and its mirror/tap. | Both legacy entry points stop before executing. The NormalSwitcher release workflow remains the publishing path. |
| No committed macOS regression suite for the task feature | Only an ad hoc smoke check had been run. | Add 25 production-code and AppKit action tests plus a macOS checks workflow. |

## Clipboard persistence follow-up

**Clipboard persistence and migration have been implemented and tested.**
History now uses entries.aesgcm with its own Keychain service. Tasks keep their
existing file format and service. Both stores share locking, snapshot comparison,
private atomic writes, and missing-key behavior. Legacy entries.json is removed
only after reading back and authenticating the encrypted file. Interrupted
migration merges distinct records on retry. Corrupt input or key failure does
not become an empty successful load. New clipboard copies remain in memory and
are merged on an explicit retry; failures do not repeatedly prompt for a key.
An explicit clear/disable operation can remove the clipboard store without its
key, and never touches tasks. The bounded store retains up to 30 unique entries.
The tests also reject stale writes and retain visible history after failed clear.
The earlier plaintext/try? load behavior was a plausible explanation for a lost
history report, not a confirmed diagnosis of that incident.

## Remaining release gates

### High priority

**Runtime and upgrade checks remain open.**
Test global shortcuts and reassignment, registration conflicts, capture focus,
Undo, Cancel/Escape, menu interaction, clipboard paste target, closing the parent
window with a dirty editor, first Keychain access, restart, and an upgrade with
the release signing identity. Exercise the updated clipboard-clear path with
persisted tasks and verify isolation end to end. The isolated tests use temporary
files and injected keys. They do not exercise the user's actual Keychain.

**Automatic conversion needs a representative live regression pass.**
The active space path has a 120 ms decision budget and skips conversion before
dictionary warm-up. The passive/deferred path intentionally abandons work when
its tracked boundary has become invalid. These can explain some missed
corrections, but this audit did not reproduce the earlier intermittent failure.
The menu now exposes permission, keyboard-hook, protected-input, excluded-app,
remote-client, trigger, warm-up, layout and missing-dictionary states. It reports
readiness rather than claiming every word will be corrected.
Test rapid typing, focus changes, wake/unlock, RU/EN and ES/EN, plus Space/Enter/Tab
in TextEdit, browser inputs, and a messenger. Do not promise universal conversion
from passing task-storage tests.

### Medium priority

- Task encryption, Keychain access, and whole-list serialization run on the main
  actor, which also hosts keyboard handling. Measure large lists and large copied
  texts before deciding on a serial background persistence queue and explicit
  size limits. Any asynchronous redesign must preserve write ordering and
  failure visibility.
- The new task interface has Russian/English strings outside the existing
  localization table. Other selected interface languages fall back to English.
- There is no single-instance guard in the reviewed startup path. Task-file
  locking protects against stale task writes, but duplicate processes can still
  compete for shortcuts and keyboard hooks.
- The updater stages in NSTemporaryDirectory while comments claim the staging
  copy is on the application's volume. An application on another volume needs
  a separately tested replacement strategy.
- This branch README now describes NormalSwitcher, links its own releases and
  Windows branch, credits the original author, and labels tasks as beta.
  Main and personal documentation should be synchronized when the feature ships.
- New builds should be tied to a source commit and the expected signing identity.
  The release workflow verifies an uploaded signed archive and its hash; it does
  not rebuild that archive from source.

## Verification and practical limits

- Local Swift build and 28 committed regression tests pass using Xcode's toolchain.
- New tests cover clipboard migration/restart, corrupt JSON/ciphertext, key denial
  and retry without repeated prompts, failed readback, interrupted/changed legacy
  migration, concurrent writers, failed clear, task isolation, disabling and
  re-enabling persistence, deduplication/limits, readiness states, and AppKit
  history search, Add to Tasks, Enter, All entries, selection and settings actions.
- AppKit actions were exercised with synthetic data in hidden windows; they do
  not establish live global-hotkey, clipboard-focus, or actual-Keychain behavior.
- Tests cover Unicode/multiline persistence, restrictive permissions, wrong-key
  and tamper rejection, missing-key behavior, stale editors, completion
  preservation, stale writes from another copy, busy-writer rejection without blocking keyboard handling, and failed writes with retry.
- The installed application's signature validates against the updater's pinned
  team requirement HDFDUW2PQ7. This is not a new-build upgrade test.
- Canonical stable/beta feed and dictionary manifest URLs returned HTTP 200. Stable reports 1.1.6, while the inherited beta reports 3.5.0g.
  The dictionary manifest contains EN and RU packs. Other languages depend on
  available system dictionaries and layout mappings.
- The new CI workflow builds/tests the macOS code. Its remote status must be
  checked separately from the local result.
- Following explicit beta approval, 1.2.0a (build 77) was published as a GitHub
  prerelease from source 6e98fd3. The beta feed points to its signed DMG. Stable
  version.json remained byte-for-byte unchanged at 1.1.6. Additional tests cover
  channel opt-in, absent/invalid beta, and promotion from beta to stable.
- The app signature passed the existing HDFDUW2PQ7 requirement; the HFS/UDZO
  image passed checksum verification. This execution environment cannot attach
  disk-image devices, so mounting and running this DMG remains a beta interaction
  check. Publication does not imply these open runtime checks are complete.

## Suggested order

1. Finish live task interaction and signing/upgrade tests.
2. Verify signed upgrade migration with a synthetic persisted history.
3. Complete the typing regression matrix and check the new diagnostic status
   against actual failures and selected layouts.
4. Review the revised clipboard and task windows with keyboard and mouse.
5. Validate the fixed-size interface on supported macOS versions and displays,
   then publish the signed build with concise release notes.
