# Перенос функций macOS 1.2.0b в Windows

## Цель

Довести Windows-версию NormalSwitcher до функционального соответствия macOS 1.2.0b в перечисленных ниже сценариях. Пользователь особенно ожидает полноценный локальный задачник, связанный с историей буфера.

Результат — проверенные изменения в отдельной ветке, PR и тестовая Windows-сборка. Отсутствующий задачник означает, что задача не выполнена.

## Исходное состояние и порядок работы

- Репозиторий — Thalassiochthon/NormalSwitcher.
- Продолжать ветку `windows/macos-parity-audit`, исходный WIP-коммит `a5b054f`. Она основана на Windows `windows-preview`, коммит `8c5bd2f`, канал 0.2.6.
- Эталон поведения Mac — тег `v1.2.0b`, коммит `c246bc757ef829da8b344954271e82b93913dcb8`. Читать Mac-файлы через git show либо отдельный worktree. Не копировать Windows-каталог из macOS-ветки, он может быть старее.
- Сначала прочитать действующие AGENTS.md, проверить git status и сохранить чужие изменения.
- Составить короткую таблицу соответствия функций. Затем выполнять этапы ниже по очереди, фиксируя изменения отдельными понятными коммитами.
- В WIP уже начаты поиск и компактная история, повторное чтение хранилища, подтверждение очистки, совместимость URL обновления. Код компилировался на macOS. Поведение на Windows ещё не проверено. Проверить и довести эти правки, не считать их принятыми автоматически.
- Уже реализованы собственные звуки с предпрослушиванием, фиксированное окно настроек, шифрование истории Windows и отдельный процесс обновлятора. Сохранить их работоспособность.
- Существующий стек — C#/.NET 8, WinForms, Win32. Использовать его и существующую локализацию RU/EN.
- Кросс-обмен буфером Mac–Windows, сервер, авторизация, проекты, категории, сроки и напоминания находятся за рамками этой задачи.

## Этап 1. Задачи как на Mac — обязательная часть

Эталон в `macos/Sources/RuSwitcher/` — `QuickTasks.swift`, `QuickTaskList.swift`, `QuickTaskStore.swift`, `EncryptedFileStore.swift`. Посмотреть также интеграцию в `AppDelegate.swift`, `ClipboardHistoryWindow.swift` и `SettingsWindowController.swift`.

### Пользовательские сценарии

- [ ] В истории буфера есть кнопка «В задачи», сохраняющая полный текст выбранной записи.
- [ ] Отдельное настраиваемое сочетание сохраняет текущий текст буфера напрямую. Это работает и при выключенной истории буфера.
- [ ] «Задачи» открываются из трея, настроек и по отдельному сочетанию.
- [ ] Окно задач допускает ручное создание, поиск по названию и тексту, редактирование, отметку выполнения, возврат в работу и просмотр выполненных.
- [ ] Редактор показывает название и полный многострочный текст. Заголовок по умолчанию берётся из первой непустой строки, максимум 120 символов с корректной обработкой Unicode. Исходный текст сохраняется целиком в пределах явного общего лимита.
- [ ] Пустой заголовок не сохраняется. Превью не заменяет исходный текст. Удаление требует подтверждения. Закрытие редактора с изменениями требует выбора пользователя.
- [ ] После быстрого добавления появляется короткое ненавязчивое подтверждение с отменой именно добавленной задачи. Успех показывается только после успешного сохранения.
- [ ] Повторное открытие активирует существующее окно. Escape, Enter и Tab работают ожидаемо, выделение после поиска остаётся валидным.

### Горячие клавиши и интеграция

- [ ] Предложить стандартные Ctrl+Shift+T для списка и Ctrl+Alt+Shift+V для сохранения буфера, как в macOS-бете. Все сочетания меняются и отключаются независимо. История по умолчанию использует Ctrl+Shift+V.
- [ ] Конфликт сочетания отображается в настройках. Неудачная смена сохраняет предыдущее рабочее сочетание. Ошибка регистрации при запуске тоже видна.
- [ ] Действие выполняется после отпускания клавиш, однократно. Открытие задач не должно зависеть от наличия текстового поля или включённого исправления раскладки.
- [ ] Не создавать вложенные модальные окна по повторным нажатиям. Проверить взаимодействие истории, редактора задач, настроек и обновлятора.
- [ ] При прямом чтении буфера использовать общую проверку допустимости текста. Уважать явный запрет записи в историю и маркеры защищённого содержимого. Не читать пароль через обход ограничений.
- [ ] Подсказки на RU/EN описывают действие простыми словами. Новые строки находятся в L10n.

### Хранение задач

- [ ] Отдельный зашифрованный файл задач в пользовательском каталоге NormalSwitcher. Использовать Windows DPAPI CurrentUser с отдельным назначением/entropy для задач.
- [ ] Минимальная модель включает устойчивый id, title, text, completed.
- [ ] Атомарная запись. При ошибке записи предыдущий файл и состояние списка сохраняются. Ошибка чтения не должна приводить к перезаписи файла пустым списком.
- [ ] Очистка или отключение истории буфера не удаляют задачи. Перезапуск и обновление сохраняют задачи.
- [ ] Учесть повторные действия, устаревший открытый редактор и конкурирующую запись. Редактирование не воскрешает удалённую задачу и не отменяет её актуальный статус выполнения.
- [ ] Не писать текст задач или буфера в диагностический журнал.

Windows-точки интеграции — `Core/Settings.cs`, `Core/GlobalShortcuts.cs`, `Core/ClipboardHistory.cs`, `UI/ClipboardHistoryMenu.cs`, `UI/SettingsForm.cs`, `Tray/TrayIcon.cs`, `Program.cs`. Выделить модель/хранилище и UI задач так, чтобы операции хранения можно было тестировать отдельно.

## Этап 2. Довести историю буфера

Эталон Mac — `ClipboardHistory.swift`, `ClipboardHistoryWindow.swift`, `ClipboardHistoryStore.swift`.

- [ ] Компактное фиксированное окно. По умолчанию 8 последних записей, «Все записи», счётчик и поиск по всей истории. Хранимый лимит 30 записей.
- [ ] Превью в одну строку, полный текст при вставке/создании задачи. Пустая история и отсутствие результатов поиска имеют разные сообщения.
- [ ] Вставка возвращает фокус нужному полю. При смене цели не вставлять в постороннее окно. Проверить отмену, выбор мышью и клавиатурой.
- [ ] Подтверждение очистки. Сначала успешная операция хранения, затем обновление списка.
- [ ] При ошибке загрузки/записи новые записи остаются в памяти, появляется понятное сообщение и «Повторить».
- [ ] Повторное чтение объединяет сохранённые записи с новыми без дублей, сохраняя порядок и лимит. Устаревший полный снимок памяти не должен затирать изменения на диске.
- [ ] Сохраняется чтение прежнего `clipboard-history.dat`. Ошибка дешифрования не трактуется как пустая история.
- [ ] Проверить WIP `RetryStorage`, который сейчас объединяет pending, весь список памяти и сохранённый список. Разделить сценарии первого включения сохранения и восстановления после ошибки.
- [ ] Проверить ограничения текста до записи и после чтения. При изменении лимитов старые записи не удалять молча.
- [ ] Проверить трактовку Windows-форматов CanIncludeInClipboardHistory и CanUploadToCloudClipboard по их значениям. Нынешняя проверка только наличия формата может отбрасывать разрешённые записи.

## Этап 3. Надёжность автоисправления и диагностика

Подтверждённые по исходникам проблемные места — `Program.cs`, `Core/InputTarget.cs`, `Core/AutoConverter.cs`, `Core/AccessibleText.cs`, `Core/Dict.cs`.

- [ ] При быстром наборе следующая клавиша увеличивает inputGeneration и сбрасывает pendingAuto. Сохранить завершённое слово для проверки и разработать безопасное применение результата с учётом текста, введённого после него.
- [ ] Сохранить защиту от применения устаревшего результата после смены поля, перемещения курсора, выделения, удаления текста или ручной смены раскладки. Простое снятие проверки поколения недопустимо.
- [ ] Enter/Tab воспроизводятся ровно один раз, в правильном порядке и правильном окне, включая отмену проверки. При неподдерживаемом редакторе текст и клавиши должны оставаться корректными.
- [ ] Устранить отказ проверки после 4096 символов в native edit. Проверить также позиции свыше 65535, потому что сейчас EM_GETSEL извлекается из упакованных 16-битных значений. Использовать подходящий безопасный Windows API с ограничением времени и объёма чтения.
- [ ] Согласовать работу системного и расширенного словаря с macOS. Различать «слово неверно» и «словарь не проверил». Наличие запасного словаря не должно означать безусловную замену неизвестного слова.
- [ ] Не зашивать все сценарии в пару RU/EN. Определять раскладку и язык целевого окна. Проверить RU↔EN и доступные сценарии испанского, включая диакритику/dead keys. При отсутствии словаря или неоднозначном результате показывать причину ограничения.
- [ ] Добавить актуальный статус автоисправления в меню/настройках по образцу `AutoCorrectionStatus.swift`. Выключено, обработчик недоступен, исключение приложения, защищённое/неподдерживаемое поле, не выбраны разделители, недоступен словарь, готово к проверке.
- [ ] Сбой регистрации обработчика и сочетаний не должен выглядеть в интерфейсе как работоспособное состояние.
- [ ] Диагностика сохраняет причины отказов и этапы обновления без содержимого введённого текста.

## Интерфейс

- Фиксированные размеры окон в логических единицах с корректным DPI-масштабированием.
- На 100%, 150% и 200% текст и кнопки доступны, без горизонтальной прокрутки. При малой рабочей области допустима продуманная вертикальная прокрутка.
- Сохранить существующий стиль NormalSwitcher и иконки. Проверить RU/EN, длинные названия, ссылки, Unicode, многострочные задачи.
- Реализовать полный пользовательский сценарий в Windows, используя подходящие Windows-механизмы. Внешний вид и подсказки должны быть согласованы с продуктом.

## Тесты и критерии приёмки

- [ ] Автотесты модели задач — создание, сохранение/повторное чтение, редактирование, completed/reopen, поиск, удаление и undo. Ошибки чтения/записи, повреждённый файл, устаревший редактор, очистка истории при существующих задачах.
- [ ] История — больше 8 записей, поиск записи за пределами первых 8, полный текст, пустой результат, восстановление после ошибки с новыми копиями, повторная попытка и отказ удаления.
- [ ] Ввод — слово+пробел+следующая буква без паузы, быстрый поток нескольких слов, смена окна/курсора/раскладки, Backspace и выделение. Длинные документы с позицией курсора >4096 и >65535.
- [ ] Горячие клавиши — занято при запуске, конфликт при смене, откат, отключение, повторное нажатие, работа задач при выключенной истории и автоисправлении.
- [ ] Обновления — стабильный/бета-канал, точные допустимые URL, неверный SHA256, переход с 0.2.6, beta→final, сохранение пользовательских данных.
- [ ] Запустить существующие тесты Windows и дополнить `windows/tests/NativeInputSmoke` сценариями реального ввода и задач.
- [ ] На Windows проверить Блокнот, браузер и доступный WPF/WinForms-редактор. Неподдерживаемые сценарии явно описать.
- [ ] Собрать x64 и ARM64. Указать отдельно, на какой архитектуре действительно выполнялись тесты.
- [ ] Локальная компиляция на Mac не считается проверкой Windows UI/Win32/DPAPI. Использовать Windows runner для исполнимых тестов, а ограничения среды честно отметить.

Команды Windows

```powershell
dotnet build windows/src/RuSwitcher.Win/RuSwitcher.Win.csproj -c Release
dotnet test windows/tests/RuSwitcher.Win.Tests/RuSwitcher.Win.Tests.csproj -c Release
```

Сценарий `windows/tests/install-upgrade.ps1` запускать в изолированной Windows-среде — предварительно прочитать, он устанавливает приложение и использует тестовые настройки.
